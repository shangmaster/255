# 学习通签到工具（自由选点 / 拍照 / 全自动位置签到）

仓库里有**两套东西**，目的不同：

| 目录 | 是什么 | 要开浏览器吗 | 适合 |
| --- | --- | --- | --- |
| [`auto-sign/`](auto-sign/README.md) | **独立自动签到程序**（Python，无依赖）。开机自启，每分钟查一次，只签位置签到，太远会自己算坐标逼近 | **不用** | 想"装好就再也不用管" |
| [`extension/`](extension/README.md) | Chrome/Edge 扩展：位置签到（地图自由选点）+ 拍照签到（本地图片），外加按时段的自动位置签到 | 要 | 想手动选点 / 要签拍照签到 |
| `photo-sign-extension/` | 精简版扩展：只做拍照签到 | 要 | 只需要交照片 |

> **为什么自动签到要单独做个程序？**
> Chrome / Edge 的 MV3 扩展**没有办法在后台主动打开网页**，页面没打开时也拿不到页面上下文。
> 要做到"开机就自己签到、不需要你碰任何东西"，只能是一个独立进程直接调接口 —— 就是 `auto-sign/`。

下面先讲 **`auto-sign/` 这套（全自动）**，扩展部分从「二、扩展」开始。

---

# 一、全自动签到（`auto-sign/`）

开机后什么都不用做：它自己查课程活动、自己签位置签到、太远就自己算坐标逼近。

```bash
cd auto-sign
python sign.py --status        # 看状态
python sign.py --install       # 装开机自启（每分钟检查一次，时段外立刻退出）
```

四个配置步骤、日志长什么样、出问题怎么办，全在 **[auto-sign/README.md](auto-sign/README.md)**。
不想记命令就双击 `auto-sign/run.bat`，它是个菜单。

---

# 二、扩展（自由选点 + 拍照）

Chrome / Edge 扩展（Manifest V3，**零依赖、无需构建**）。仓库里有两个独立扩展：

| 目录 | 是什么 | 面板 |
| --- | --- | --- |
| `extension/` | 完整版：位置签到（地图自由选点）+ 拍照签到（本地图片），按活动类型自动切换，**外加按时段自动完成位置签到** | 蓝色「选点 / 签到」 |
| `photo-sign-extension/` | 精简版：**只做拍照签到**（自动取编号、选本地图、上传、提交），没有地图和坐标 | 紫色「拍照 / 签到」 |

两个可以同时装，互不干扰。协议代码（活动列表 / 活动详情 / 网盘上传 / 签到参数）两边共用一份，
`tools/validate-extension.mjs` 会逐字校验两份 `lib.js` 的关键函数是否一致，防止改一边忘了另一边。

## 一、先说结论：哪些能签、哪些不能

位置签到的坐标是**客户端自己传的**，服务端只按你传的 `latitude` / `longitude` 算和老师设定点的距离：

```
GET https://mobilelearn.chaoxing.com/pptSign/stuSignajax
    ?name=姓名&address=地址&activeId=签到编号&uid=你的uid&clientip=
    &latitude=30.123456&longitude=120.123456&fid=学校&appType=15&ifTiJiao=1
```

拍照签到走**同一个接口**，把坐标换成图片编号（`objectId`），用 GET、极简 9 参数：

```
activeId / uid / clientip / latitude(-1) / longitude(-1) / appType / fid / objectId / name
```

普通签到则是 8 参数（不带 `objectId`）。返回 `success` 就是签到成功。

### 能力边界（很实际，请先看这张表）

| 签到类型 | 网页端能不能签 | 说明 |
| --- | --- | --- |
| 普通签到 | 能 | 直接提交 |
| 位置签到 | 能 | 用完整版选点 |
| 普通 + 老师要求拍照 | 部分 | 能传图能提交，但服务端可能要"本机拍摄凭证"，见下 |
| 二维码签到 | 不能 | 提交要二维码里的 `enc`，只在老师屏幕上、几十秒轮换 |
| 签到码 / 手势 | 不能 | 要老师给的数字码 / 3×3 手势轨迹，本扩展不做 |
| 位置 + 人脸 | 不能 | 要人脸活体凭证 |

**关于"要求参与人拍照"**：这是老师发签到时的一个开关（叠在任意类型上）。网页端把照片传上去、
带上 `objectId` 提交，服务端可能回 `photoAuthError_PCR007` —— 它要的是**本机现场拍摄的凭证**。
学习通自己的 H5 签到页在这种情况下也是直接拦住、只提示"请使用手机APP，在本课程任务下签到"；
官方客户端的拍照字段 `photoResult` 只从原生桥（`CXJSBridge`）产生，网页端拿不到。
所以这类签到，网页端最多"试试"，要稳妥就用 APP 拍。

## 二、签到类型是怎么判定的（踩过两个坑）

`ifphoto` **不是签到类型**，它只是"老师要求参与人拍照"的附加标志。一个普通签到可以要求拍照，
一个二维码签到也可以要求拍照。所以判定分两层：

- **基础类型**（决定要什么才能签上）：普通 / 位置 / 二维码 / 签到码 / 手势
  只认服务端类型字段：`activeSort`（最准，来自**活动详情**接口）→ 其次 `otherId` → 两个都没有才按**活动名字**猜
- **附加要求**：`needsPhoto`（要求拍照）、`needsFace`（要人脸）

两个实测教训（都写进了回归测试）：

1. **`ifrefreshewm` 不是类型标志**。它只是"允许二维码自动刷新"的能力位（默认就可能是 1）。
   早期版本拿它判类型，把「普通签到 + 要求拍照」全误判成二维码签到。
2. **活动列表里的 `otherId` 未必可靠**，`activeSort` 才对得上。所以拿到编号后会再查一次
   `GET /v2/apis/active/getPPTActiveInfo?activeId=...`，用 `activeSort` 定类型。

面板会把判定依据整行摊开，例如：

```
签到类型：普通 · 老师要求拍照
判定依据：activeSort=3 · otherId=1 · ifphoto=1（要求拍照） · ifrefreshewm=1（二维码刷新能力）
```

名字和字段冲突时还会标「注意：名字像「二维码」但字段说是「普通」」。判定不再是黑盒。
认出来是二维码 / 手势 / 签到码 / 位置时，面板会**直接拦住不发请求**，并说明该用 APP 还是别的插件。

## 三、`activeId` 是怎么自动获取的
三级依次尝试：

1. **页面自己的签到请求**：注入脚本钩住 XHR / fetch，`stusignajax` / `presign` / `activelist`
   这类请求连同响应体一起回传，从里面挖 `activeId`；
2. **课程活动列表 + 活动详情**（关键路径）：用你的登录 Cookie 请求

   ```
   GET /v2/apis/active/student/activelist?fid=&courseId=&classId=&showNotStartedActive=0
   GET /v2/apis/active/getPPTActiveInfo?activeId=...
   ```

   列表里 `status` 1=进行中、2=已结束、缺省=未开始，只取进行中的、多个取开始时间最新的；
   详情里拿 `activeSort` 等字段定类型；
3. **粘贴解析**：把老师发的签到消息/链接粘进来，正则抽参数（完整版的兜底）。

配套细节：

- **课程 / 班级编号**：先看页面地址（`courseid` / `clazzid`、`courseId` / `classId` 都认），
  地址里没有就从页面正文挖，再从被钩子捕获的请求地址里补；
- **`fid` / `uid`**：`uid` 是 HttpOnly，后台用 `cookies` 权限读 `_uid` / `fid`；
- **姓名**：启动时会从账号页读出真名自动填（请求里 `name` 为空也能签，但填上更稳）；
- **重试节奏**：没拿到编号时每 6 秒看一眼、30 秒才真发一次请求，拿到就停；
- **没登录**：服务端会 302 到登录页，扩展识别后直接提示去登录，而不是丢一个空错误。

## 三·五、自动签到（**只做位置签到**）

设置页第二张卡片。默认参数就是 **周一至周五 08:00-14:00**，可以自己改成任意时段 + 任意星期。

### 不需要先打开课程页面

自动签到会自己解决「监控哪些课」这个问题，按这个顺序：

1. **设置页勾选的课程**（点「从课表读取我的课程」→ 勾上要盯的课）—— 最精确，查询最少；
2. 没有勾选就用**打开页面时自动登记**的课程；
3. 都没有就**直接拉课表**（`mooc1-api.chaoxing.com/mycourse/backclazzdata`），
   用浏览器登录态认出你的全部课程/班级，缓存下来避免每分钟重复拉。

所以正常情况下你只需要：**浏览器登录着学习通 + 选一个大概位置 + 打开自动签到**，
之后连课程页面都不用开。

### 只做位置签到，别的类型一律不动

到点后后台自己去问各门课的活动列表，一次只处理「进行中」的那一个，判定完类型：
`activeSort=4/5` 或 `otherId=4` → 位置签到，动手；其它一律只写一条日志（"检测到 XX 签到，不自动处理"），
不提交、不重试、不猜参数。这条是有意为之：普通签名可以硬发，二维码/手势/签到码/人脸在网页端本来就拿不到凭证，
自动重试只会不停打服务端。

### 离签到地点太远时：用服务端返回的距离做三点定位

位置签到被拒时，服务端的话术里一定带着距离，例如

```
签到失败，您当前距离签到地点还有1568米，请到签到地点后再试
```

这句话本质上就是一次**测量**：以刚提交的点为圆心、`r = 该距离` 的圆上一定有签到地点。
所以自动流程是这样逼近的：

1. 用你选的那个点先交一次 —— 拿到第 1 个圆；
2. 换个方向再交 —— 第 2 个圆（两个圆交出两个镜像解，方向还定不下来，此时**不瞎猜**）；
3. 再换个方向 —— 第 3 个圆，三个圆只交于一点，签到地点就定了；
4. 之后每轮都重算一遍：残差大就按"离已有测量方向最远"的方位继续撒点测；
   残差已收敛（默认 < 25 m）就改成在解附近按十字方向一次挪十几米，把最后那点距离磨掉；
5. 直到服务端回 `success`，或者判明不是距离问题（要人脸、已结束、只差几米还在拒…）就停手。

状态页会把每一步摊开给你看：

```
自动签到：已签到：测试课程「位置签到」 · 时段 周一至周五 08:00-14:00
进度：第 4 次提交 · 还差 180 m · 算出的签到点 38.041270, 114.512348（残差 0 m）
今天：查询 6 次 · 提交 4 次 · 成功 1 次
```

日志区（设置页或 popup）会逐条记：哪次提交、还差多少米、算出的坐标和残差、下一步往哪个方向。

### 时段是硬约束

- 只在设定的星期 + 起止时间内干活；时段一结束就收工，每个时段最多连续找 3 小时；
- 结束时刻之后留 12 分钟"收尾"（如果这一轮已经在逼近，让它走完）；
- 支持跨夜时段（例如 `22:00 - 02:00`）；星期全不选 = 每天都跑；
- 签上之后默认当天不再查（`签上之后` 那个勾可以关掉，改成继续盯着）。

### 时间粒度说明（浏览器限制，不是偷懒）

`chrome.alarms` 在 MV3 里最短周期是 **30 秒**，所以"每 20 秒查一次"是靠一次性的 alarm 自己续排：
每次触发后立刻排好下一次，service worker 被回收也不影响（状态全在 `chrome.storage.local`）。
另外后台额外保留每 1 分钟的兜底 alarm，用来在时段开门/跨零点时把节奏接上。

### 前提

- 浏览器要保持登录 `chaoxing.com`（扩展用的是浏览器的登录态，**不存在 cookie 过期要重新导出**的问题）；
- 需要先有一个选点（面板选一个大概位置就行，差得远它会自己逼近）；
- 浏览器得开着（扩展靠浏览器的定时器活着）。

> 关于「完全不用开浏览器」：那是 `auto-sign/` 那套独立程序能做到的，
> 但它需要一份带 `JSESSIONID` 的 cookie，且会过期。两套方案的取舍见 [第一节](#一全自动签到auto-sign)。

### 联调：确认这条链在你账号上真的通

```bash
node tools/live-check.mjs                         # 只测接口连通
node tools/live-check.mjs --cookie "k=v; k2=v2"   # 用真实登录态跑「课表→活动列表→类型判定」
```

**注意**：`JSESSIONID` 是 HttpOnly 的，`document.cookie` 和多数"复制 cookie"的做法都读不到，
必须用 **EditThisCookie / Cookie-Editor** 这类扩展导出，或者直接在 `chrome://settings/cookies` 里看。
联调脚本**不会提交任何签到**，只报告它看到了什么。

## 四、安装

1. `chrome://extensions`（Edge 是 `edge://extensions`）→ 打开**开发者模式**
2. **加载已解压的扩展程序** → 选目录：
   - 完整版：`C:\Users\s\Documents\deepseek-harness\default-workspace\chaoxing-location-picker\extension`
   - 精简版：`...\chaoxing-location-picker\photo-sign-extension`
3. 建议把图标固定到工具栏

> 需要 Chrome / Edge 111+（完整版内容脚本的 `world: "MAIN"` 需要 111）。
> 改过文件后，必须在扩展页点一次**重新加载**，再刷新学习通页面。
> 面板只会出现在 `*.chaoxing.com` 的页面上（浏览器设置页等内部页面注入不了），
> 默认是**右下角一个小圆按钮**，点它才展开。

## 五、使用

**完整版（位置 + 拍照）**

1. 打开学习通课程页面，右下角蓝色「选点 / 签到」按钮 → 点开面板；
2. 面板顶部会显示这次签到要什么（位置 / 拍照 / 二维码…），可以手动切换；
   - 位置签到：地图选点、或用「按地址搜索」；填「签到地址」文本；
   - 拍照签到：点虚线框选本地图片 / 把图拖进面板 / Ctrl+V 粘贴，当场校验并显示缩略图；
3. 点「直接签到」（拍照模式下是「上传并签到」，一次点击完成上传 + 提交）；
4. 想先看参数，点「试运行」。

**精简版（只做拍照）**

1. 右下角紫色「拍照 / 签到」→ 点开面板，它会自动查这门课的活动并判定类型；
2. 普通签到：点 **「按普通签到提交（不交图）」**；要交图点 **「提交拍照签到（交图）」**；
3. 识别成二维码 / 手势 / 签到码 / 位置时，面板直接告诉你该用 APP 或哪个插件，不会白发请求；
4. 「手动填写 / 排查」里有：手填 `activeId`、姓名、**附加参数**（`photoResult=xxx&foo=bar`）、
   自动获取编号、**探测拍照协议**、检查上传通道、复制诊断。

## 七、可能遇到的问题

| 现象 | 原因 / 处理 |
| --- | --- |
| 看不到面板 | 只支持 `*.chaoxing.com`；装好/改过后要在扩展页**重新加载**并**刷新页面**；右下角是小圆按钮，需要点开；控制台应出现 `[拍照签到插件] 面板已挂载` |
| 识别不到 `activeId` | 先点「自动获取编号」/「刷新识别」；多半是没登录，或页面地址里没有课程编号（先去课程页面） |
| 提示"没有进行中的活动" | 老师还没发签到，或已结束。页面开着，每 30 秒会自动再查 |
| `photoAuthError_PCR007` | 服务端要本机拍摄凭证（`photoResult`，只从原生桥产生）。先试「按普通签到提交（不交图）」；不行就用 APP 拍 |
| 返回「签到失败，请重新扫描」 | 这是二维码签到，要老师屏幕上的 `enc`，网页端拿不到，用 APP 扫 |
| 返回 `validate` | 要防作弊验证码（可试试无痕 / 换网络；扩展本身不做验证码） |
| 返回「请先登录再进行签到」 | 登录态失效，重新登录 `i.chaoxing.com` |
| 提示"图片太大 / 不是常见图片格式" | 上限 10 MB，只收 jpg / png / webp；先截屏或压缩 |
| 地图一片灰 | 瓦片被拦，换 OpenStreetMap 或直接手填经纬度 |
| 自动签到不动 | ①设置页确认已开、时段/星期对得上；②先在对应课程页面打开过一次（后台才知道去查哪门课）；③要有选点；④看设置页日志里的原因 |
| 自动签到一直"还差 xxx 米" | 允许范围特别小或有设备校验时会这样；日志里会写"已经签上就停"还是"判明不是距离问题"。可把上限 maxRounds 调大，或先手动选个更近的点当起始点 |

## 八、边界与风险

- **合规**：签到本质是考勤，改位置或用非现场照片，风险自负；只在自己的账号设备上使用，不要代他人签到。
- **服务端可能加校验**：目前能通，是因为服务端信任客户端上报的坐标；一旦加签名、时间戳、设备指纹、
  IP 归属地比对或照片现场性校验，网页端方案就会失效。
- **拍照签到的硬边界**：`photoResult` 由原生桥产生，网页端没有生成路径，这不是参数能修的。
- **图片会上传到你的学习通网盘**：换 `objectId` 必须如此；扩展不会把图片发到第三方，也不存进本地存储。
- **自动签到只是"省手"**：它仍然走和手动一样的接口与参数，不会伪造设备指纹；服务端一旦加上"必须本机 APP 上报"
  这类约束，网页端包括本扩展都会失效。
- **隐私**：扩展只读写本地 `chrome.storage`；网络请求都发往 `chaoxing.com`（你已登录的站点）；
  地址搜索那一步才会用到高德 / OSM，且只发地址文本。
